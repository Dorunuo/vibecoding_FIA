## 木盒碰撞体

每个木盒的统一碰撞尺寸为 **1.36 × 1.08 × 0.80米**（Blender X/Y/Z）。代理覆盖盒身、盒盖、金属带及锁扣，并留少量余量，避免角色碰撞体只挡住盒身而穿入盖子或配件。

- 二层盒：代理中心 Blender `(0,9,-4.6)`；Three.js `(0,-4.6,-9)`。
- 三层盒：代理中心 Blender `(0,6,-9.6)`；Three.js `(0,-9.6,-6)`。
- Three.js 尺寸为 `(1.36,0.80,1.08)`，Y向上。
- Blender 中代理有实际 PASSIVE 被动刚体、BOX碰撞形状和0.01米碰撞余量，不只是写在说明中的标记。
- 代理在普通视口隐藏、渲染关闭，避免与可见木盒重叠。展开 COLLISION_Proxies 集合可检查。
- 所有实体木盒顶点均已做包围验证；金光透明面片与局部点光不参与实体碰撞。
- 大厅土堆提供三角网格碰撞代理，标记 walkable，不能用高大AABB把大厅路堵住。玩家如何在土堆表面抬升仍由地面支持面系统实现。

## 游戏接入：不能省略

**GLB 本身不会自动让 Three.js 玩家发生碰撞。** Blender 的被动刚体也不会自动变成原游戏的碰撞逻辑。这里提供了真实代理、尺寸清单与可测试示例，但尚未取得原游戏控制器源码，因此不能宣称实际游玩已经通过“不穿盒子”验收。

接入步骤：
1. 继续使用原场景的墙/柱/楼板碰撞，在其上注册这两个盒子AABB；或把独立碰撞GLB的几何导入所用物理引擎，并设置静态实体。
2. 使用玩家完整碰撞体/身体高度，不能只测试脚点是否在盒子内部。
3. 高速移动或较大帧间隔需要连续扫掠或子步，不能只检查移动结束位置。
4. 支持玩家落到盒盖上，并在头顶/侧面接触时正确阻挡；交互点应设在盒外，不要要求玩家走进盒中心。
5. 若盒子收取后保留，只关掉金光和光源，继续保留碰撞；若整个盒子移除，碰撞代理也同步移除。
6. 若旧 C 模块仍在程序中生成蓝色晶体，需要停用旧占位视觉，否则会与新版模型叠加。

## 可选连续碰撞示例

示例接口使用普通 `{x,y,z}`，坐标为 Three.js Y向上。传入的是玩家**脚底中心位置**，不是胶囊中心；半径、身高必须与实际控制器一致。

```js
import { resolveTreasureBoxMove } from './treasure_box_collision.mjs';
const result = resolveTreasureBoxMove(
  currentFeetPosition, candidateFeetPosition,
  playerRadius, playerHeight,
  collisionData.boxes
);
// 把 result.position 交回控制器；再结合已有墙体、地面、重力处理。
// result.normal.y === 1 可以作为盒盖落地接触信息。
```

该函数采用保守的三维扩张AABB扫掠，停止在第一次碰撞前约2毫米，避免大步跨过盒子。它不是完整角色控制器：没有滑墙、台阶、斜坡、移动平台或初始重叠恢复。若 initialOverlap 为 true，必须纠正出生点/初始角色位置，不要把角色继续放在盒内。

配套独立测试覆盖正面/侧面阻挡、高速穿越、落到盒盖、盒顶通行、跳越、绕行、初始重叠检测等。测试通过不等于原游戏已集成；实际走动、跳跃、相机和碰撞仍需在游戏里复测。
