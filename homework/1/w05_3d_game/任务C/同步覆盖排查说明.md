# 同步队友文件后无法交互：排查与修复

## 原因

当前运行目录 `src/` 的 gameplay.js、collectibles.js、exit.js 被同步成早期占位实现；任务C目录仍保存已验收的完整实现。

- gameplay.update 只调用 collectibles.update(dt)，未向其传递输入、角色快照和角色动作接口；计数、开门、胜利逻辑均缺失。
- collectibles.update 仅旋转晶体，不处理 E 键，不进入采集状态。
- exit 没有门体动画和进入区域检测。
- main 的开始/恢复画布聚焦衔接也丢失，但 B 的新版 input 已改为 window 监听，所以不能把此次无法采集简单归因于旧版焦点故障。

修复前运行 `node 任务C/第2批自动测试.mjs`，第20行失败：应出现 exit_locked，实际返回空事件数组，复现玩法回退。

## 修复

1. 修改前的五个运行文件保存于 `任务C/同步覆盖修复备份-20261107-094042/`。
2. 从任务C的已验收副本恢复 src/gameplay.js、src/collectibles.js、src/exit.js。
3. main.js 补回开始、重开及恢复时先更新 UI 再聚焦画布。
4. 保留队友新版 input 的 window 键盘监听、手柄支持、鼠标拖动与归一化；仅补画布 tabindex、画布失焦清键及 dispose 恢复 tabindex。
5. 主游戏输入自动测试适配 window 监听、真实鼠标按钮字段和新版 player 所需 playerRadius。

## 验证

- 第2批自动测试通过：采集、计数、防重复、开门、实际出口胜利、暂停、复位和资源释放等。
- 主游戏输入自动测试通过：真实 player 位移、键盘边沿、失焦清理与监听释放等。
- main.js/input.js 语法检查通过。
- 上述为模块和 DOM 替身自动测试，不代表本次浏览器人工验收已完成。
